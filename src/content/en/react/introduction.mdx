# Introduction to React

React is a JavaScript library for building user interfaces with reusable, composable components.

---

## What is React?

React is:
- **Component-based** — build UIs from isolated, reusable pieces
- **Declarative** — describe what the UI should look like, React handles updates
- **Virtual DOM** — efficient DOM updates without manual DOM manipulation

---

## Components

React apps are trees of components:

```jsx
// Functional component (the modern standard)
function Welcome({ name }) {
  return <h1>Hello, {name}!</h1>;
}

// Using the component
function App() {
  return (
    <div>
      <Welcome name="Alice" />
      <Welcome name="Bob" />
    </div>
  );
}
```

### Class vs Function Components

| Feature | Class Component | Function Component |
|---------|----------------|-------------------|
| Syntax | `class extends React.Component` | Plain function |
| State | `this.state` | `useState` hook |
| Lifecycle | `componentDidMount` etc. | `useEffect` hook |
| `this` binding | Required | Not an issue |

> **Interview Tip:** Function components with hooks are the modern standard. Class components are legacy.

---

## JSX

JSX is a syntax extension that looks like HTML but compiles to JavaScript:

```jsx
const element = <h1 className="title">Hello World</h1>;

// Compiles to:
const element = React.createElement("h1", { className: "title" }, "Hello World");
```

### JSX Rules

```jsx
// Must have a single root element (or fragment)
return (
  <>
    <h1>Title</h1>
    <p>Content</p>
  </>
);

// Embed JavaScript with curly braces
const name = "Alice";
<h1>Hello, {name}</h1>

// Use className (not class) — class is a reserved word
<div className="wrapper">...</div>
```

## Props

Props are read-only inputs passed to components:

```jsx
function Card({ title, children }) {
  return (
    <div className="card">
      <h3>{title}</h3>
      {children}  {/* children prop = nested content */}
    </div>
  );
}

<Card title="Hello">
  <p>This is card content</p>
</Card>
```

> **Key Rule:** Props are **immutable** — a component must never modify its own props.

---

## State vs Props

| Props | State |
|-------|-------|
| Passed from parent | Owned by the component |
| Immutable | Mutable |
| Triggers re-render on change | Triggers re-render on change |
| Like function parameters | Like local variables |

---

## The Virtual DOM

React maintains a lightweight representation of the real DOM:

1. React renders to a **virtual DOM tree**
2. On state change, React creates a **new virtual tree**
3. React **diffs** the old and new trees (reconciliation)
4. React applies only the **minimal real DOM updates**

> **Interview Tip:** This is why React is efficient — it batches updates and minimizes expensive DOM manipulation.

---

## Interview Summary

- React is declarative and component-based
- Function components + hooks are the modern standard
- JSX compiles to `React.createElement` calls
- Props are immutable, state is mutable (owned by component)
- Virtual DOM + reconciliation = efficient updates
- `children` prop allows component composition
