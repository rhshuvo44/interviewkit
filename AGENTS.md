# InterviewKit Project

## Git Workflow

Work directly on `main`. After completing ANY task (feature, fix, refactor), always:

1. Stage all changes: `git add .`
2. Commit with a descriptive message following conventional commits:
   - `feat: add new feature`
   - `fix: resolve bug`
   - `refactor: improve code structure`
   - `docs: update documentation`
   - `style: formatting changes`
3. Push to remote: `git push`

Do NOT ask for permission to commit and push. Just do it automatically after finishing work.

## GitHub MCP Usage

Use the `github` MCP tools for:
- Creating and managing repositories
- Opening pull requests
- Managing issues
- Listing branches and commits on remote

Use `bash` for:
- Local git operations (add, commit, push, pull, branch)
- Package management (npm, npx, node)
